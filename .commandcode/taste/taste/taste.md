# Taste
- Frames web projects as educational problem-solving tools: content, copy, UX, and SEO should emphasize teaching (learning forex/automated trading, avoiding scams, safely installing/testing EAs) over pushing downloads or sales. Confidence: 0.8
- Prefers reusing the established design/layout of a site they already operate rather than designing fresh UI — e.g. instructed that new pages should mirror the product-page layout/design of their existing marketing site (strivealgo.com). Confidence: 0.6
- Runs content sites as an ad-monetized business: monetises via Google AdSense plus affiliate links (broker/product referral links), and prioritises organic search traffic — so every layout must be built for SEO and AI/GEO (generative-engine) visibility, not just aesthetics. Confidence: 0.7
- Wants substantive, original long-form content rather than filler — explicitly requires posts to be a defined long word band (3,500-7,500 words) that solve real problems, with no duplicate content, and every post to carry a download/asset that solves a real problem. Confidence: 0.6
- Wants marketing, blog and product-review copy written in the Alex Hormozi direct-response framework: a powerful headline, then the customer's biggest problem, agitate that pain with a short story, present the offer as the only logical solution, a detailed offer breakdown, and a strong closing call to action. Confidence: 0.7
- Prefers simple, direct, plain language in user-facing copy (second-person, short sentences, no jargon walls) aimed at a broad target audience. Confidence: 0.6
- Requires content to comply with platform advertising guidelines — Google/AdSense and Facebook/Meta — avoiding banned claims (guarantees, "risk-free", get-rich/income promises), fake scarcity, and misleading imagery. Confidence: 0.6
- Wants repo-level canonical, AI-facing spec/standard documents (e.g. an AGENTS.md entry point plus docs/ standards for content, design and per-post briefs) so any AI or developer reproduces the same output consistently. Confidence: 0.7
- Wants to review a step-by-step plan and approve it before any work is executed — asks to see "the plan and what you are going to do step by step" up front rather than letting the agent dive into changes. Confidence: 0.6
- Wants content pages rendered full-width with no sidebar ad column, prioritising a clean, modern, uncluttered reading experience over ad density. Confidence: 0.55
- Judges UI by whether it feels genuinely "premium" against strivealgo.com, not merely on-theme — a palette/token swap alone is not enough; they expect the full polish layer (glowing/animated backgrounds and orbs, glass header that solidifies on scroll, gradient pill buttons, mega-menu dropdowns, cards that lift/glow on hover, restrained motion). Confidence: 0.65
- Wants ambient motion as part of the premium feel and keeps asking for more of it, not less — explicitly requests effects like a falling particle field and a cursor/mouse-following glow layered behind the content. Confidence: 0.6
- Wants freshness signals for SEO/GEO: current month and year (derived at build time) should appear in page titles, on-page labels, and structured data (e.g. dateModified) so the site reads as recently updated. Confidence: 0.6
- Drives work in pre-approved phases and advances them with terse commands (e.g. a bare "start next", or "check the plan and start from the last day session"), expecting the agent to keep executing the plan autonomously without re-explaining or re-confirming each step — and explicitly does not want the agent to pause or idle between sessions or batches: on finishing one session/batch it should immediately start the next item in the queue rather than stopping to ask or wait. Confidence: 0.7
- Treats a persisted plan file (in ~/.commandcode/plans) as the source of truth across sessions: on resuming, expects the agent to find the plan, work out where the previous session actually stopped (from live state — recent file timestamps, queue files, check reports — not just the plan text), and continue the rollout from the top of the priority queue rather than re-planning. Confidence: 0.6
- Tiers AI models by workload share: `meta/muse-spark-1.3-contributor` for ~70-80% routine work (Astro coding plus 3,500-7,500-word rewrites done section by section), `deepseek/deepseek-v4.1-flash` for ~15-25% complex work (debugging, architecture, code review, and factual/structural review of rewrites), and `gpt-5.6-sol:low` for ~1-5% critical planning and major architecture/content-strategy decisions. Confidence: 0.95
- Monitors usage limits via the `/usage` command; falls back to `meta/muse-spark-1.3-contributor` when a premium model hits its limit and resumes premium work only when limits reset, rather than pausing work entirely. Confidence: 0.95
- Always wants task-completion reports to identify which model was used. Confidence: 0.95
- Wants scope decisions made visible in the completion report: deliberate deferrals/omissions must be flagged explicitly (as "deliberate, not skipped by accident") and open security concerns surfaced, rather than left silent. Confidence: 0.55
- Wants the running site surfaced to them for review, and expects the dev/preview server to be started and left running — explicitly told the agent to "show the website, do not close until i close," so the server must stay up until they say otherwise (only the agent's own automation browser may be closed). Confidence: 0.7
- Wants in-progress work persisted to a durable backend task ledger (not just chat or a plan file) — record each phase/task with status, dependencies and result so any AI model or human can pick up the remaining work cold. Confidence: 0.8
- Prefers self-hosting site assets over third-party CDNs — fonts (and similar assets) should be fetched and committed locally, the built output must contain zero third-party (e.g. Google Fonts) requests, and this should be scripted/reproducible rather than hand-managed. Confidence: 0.6
- Treats accessibility as a hard, verified requirement rather than a nice-to-have: keyboard operability, deliberate focus management (open/close/focus-restore), ≥44px touch targets, exactly one H1 per page and no horizontal overflow — enforced by automated Playwright + axe tests wired into the release gate. Confidence: 0.6
- Prefers build-time/static solutions over runtime-JavaScript-only patches — fixes should work even when scripts never run (e.g. patching markdown tables with a rehype plugin at build time instead of a client-side patch). Confidence: 0.5
- Wants visual review of pages at both desktop (1440×1100) and mobile (390×844) viewports, not a single screen. Confidence: 0.5
- Runs large content rollouts in waves of parallel sub-agents, one file per agent, each assigned a distinct angle so adjacent posts cannot collapse into duplicate content, and each self-verifying against the strict content gate before reporting back. Confidence: 0.55
- Requires published assets and links to be factually verified, not guessed: every download/source URL must actually resolve (2xx/3xx, probed with curl) before it ships, and every internal link must point at a real existing slug using trailing-slash root-relative paths — guessed or truncated slugs are a gate failure to be caught and fixed. Confidence: 0.6
- Wants release gates to be trustworthy: hard-fail on a real problem (e.g. an HTTP 404/410 dead download) but not on transient conditions (timeouts/network errors retried, then downgraded to warnings), because a flaky gate that false-fails trains people to ignore it. Confidence: 0.55
- Keeps structured content in frontmatter and lets the layout render it: FAQs, sources and install steps live only in frontmatter (the body must not repeat them), with exactly one H1 supplied by the template rather than the Markdown body. Confidence: 0.5
- Wants per-post variety in the downloadable asset each post offers: the download library must not keep serving the same few files — each post should offer a distinct, verified asset, with distinctness enforced by an automated gate rather than left to judgement. Confidence: 0.8
- Scopes the long-form word-count band to article/guide posts only: product (buying) pages are exempt from the band and instead must earn the purchase decision with charts, graphs, real data and concrete evidence (metrics, specifications, licence tiers, stated account type, honest limitations) rather than length — padding a buying page to hit a word count actively makes it worse. Confidence: 0.8
- Insists charts and visual decision aids be drawn only from real data they actually hold — figures must come from verifiable sources and be labelled with when they were checked; if no real record exists, the page should say so plainly rather than plot an invented curve or estimate. Confidence: 0.7
- Wants tool/skill adopt-or-update operations done conservatively and in a fixed order: identify the platform's supported install path, detect whether it is already installed, compare the installed version against the latest stable release, and show exactly what will change — only then install/update, and never overwrite when nothing actually differs. Confidence: 0.6
- Prefers official/native installers for third-party packages and, when none exists (or the documented download path is broken), falls back to the official complete package or upstream source (e.g. the project's GitHub release asset) rather than trusting the listing's own download link blindly.
