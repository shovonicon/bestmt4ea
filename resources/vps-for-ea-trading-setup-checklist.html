VPS for EA Trading: Setup & Latency Checklist

A VPS keeps your EAs running when your home internet or power does not — but a badly chosen VPS adds latency, restarts for updates at the worst moment, and silently logs you out of the terminal. Choose and configure it with this checklist.

1. Choosing the server

  • Location beats specification: pick the data centre closest to your broker's trade server, not closest to you. Ask the broker where their server is (often London, New York or Amsterdam).
  • Minimum practical spec for 1–3 terminals: 2 vCPU, 2–4 GB RAM, SSD storage, Windows Server.
  • Test latency before committing: ping the broker's server from the VPS; under 10 ms is excellent, under 50 ms is workable for most EAs, above 100 ms hurts scalpers.
  • Monthly price is the wrong place to save $5: a single missed stop during a home outage costs more.

2. First-hour configuration

  • Change the default administrator password; create a separate login if the provider allows it.
  • Windows Update: set active hours outside your trading sessions and disable automatic restart while logged in. More EAs die from update restarts than from crashes.
  • Power plan: High performance; disable sleep and display timeouts.
  • Install only the terminals you use. Every extra program is memory your EA does not get.
  • Set the terminal to start with Windows (Startup folder), and enable "auto-login" so a restart recovers the session unattended.

3. Weekly health check (10 minutes)

  • Terminal connected, AutoTrading on, EA icons uncrossed on every chart.
  • Free disk above 20%: log files grow quietly and a full disk stops the terminal mid-trade.
  • Journal tab scanned for "disconnected" clusters.
  • One test: close and reopen the terminal to prove it recovers cleanly.
The VPS rule: a VPS is not a backup. Keep your EA files, .set files and this checklist somewhere else as well — if the VPS dies on Sunday night, your Monday should be an inconvenience, not a rebuild.
